## Why

Создание mock тестов для внутреннего репозитория (internal/repository) необходимо для обеспечения надежной и качественной работы приложения. Тестирование позволяет выявлять ошибки на ранней стадии разработки и гарантирует стабильность функциональности при внесении изменений в код.

## What Changes

- Добавление mock тестов для всех функций в internal/repository
- Реализация unit тестов для проверки логики работы репозитория
- Создание фиктивных данных для тестирования запросов к базе данных

## Capabilities

### New Capabilities
- `repository-mock-tests`: Создание mock тестов для репозитория
- `database-mock-queries`: Тестирование запросов к базе данных с использованием моков

### Modified Capabilities
- `data-storage`: Требования к хранению данных изменены для обеспечения тестирования

## Impact

- Повышение качества кода и надежности приложения
- Упрощение процесса разработки и внесения изменений
- Обеспечение функциональности тестирования данных в репозитории
